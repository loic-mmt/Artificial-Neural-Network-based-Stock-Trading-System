# Data Preparation & Labeling

* **Triple Barrier Method:** Replace fixed return thresholds with dynamic barriers based on local volatility, such as **ATR** or **Bollinger Bands**.

  * **Current status — IMPLEMENTED, BENCHMARK PENDING:** `triple_barrier` supports `--label-volatility-estimator rolling_std|atr|bollinger` in static comparison, walk-forward, and walk-forward grid search. The default preserves historical return-volatility barriers. ATR uses the simple rolling mean of adjusted true range / current price; Bollinger uses normalized ±2σ half-width (`2 * population std(price) / mean(price)`). ATR requires valid `high`, `low`, and `close`, aligned to the label price via `price / close`. All scales use historical data through the event close and are frozen at entry. Profit/stop multiples, estimated costs, close-based first touches, vertical barrier, and explicit between-event policies remain supported. CUSUM still uses return volatility independently of the chosen barrier scale; warmup and split-tail exclusions remain in place. Configuration, hashes, label metadata, and notebook reconstruction retain the estimator; old runs default to `rolling_std`. Tests cover formulas, OHLC adjustment/validation, causal and ticker isolation, config/CLI, notebook compatibility, and small training/walk-forward runs.
  * **Remaining:** Benchmark `rolling_std`, `atr`, and `bollinger` with identical data, splits, seeds, models, and execution costs. Compare perfect-label net P&L, label balance/event frequency, and out-of-sample model results; then tune barrier multiples on validation only. ATR and Bollinger widths differ in magnitude, so identical multiples are an initial ablation, not equivalent trading risk. Implementation does not establish profitability or learnability. Intraday high/low touch detection and moving Bollinger-band touches are not implemented by this scale selector.

* **FracDiff (Fractional Differentiation):** Apply fractional differentiation (`d ∈ (0,1)`) to price series to achieve stationarity while preserving as much long-term memory as possible.

  * **Current status — IMPLEMENTED, BENCHMARK PENDING:** Optional `--fracdiff` adds `fracdiff_log_price` to technical or market inputs for every model. Fixed-width binomial weights operate on log price, with an explicit coefficient threshold and bounded memory; reaching the bound before convergence raises an error. Automatic mode chooses the smallest feasible `d` in `0.1, 0.2, ..., 0.9` passing ADF (`regression="c"`, `autolag="AIC"`, default p-value ≤ 0.05), independently per ticker and using training data only. Feasible candidates are compared on identical training dates. Validation/test reuse frozen weights and causal historical context; walk-forward refits only on each historical training partition. `--fracdiff-order 0.5` freezes a manual order without claiming stationarity. Candidate p-values, correlation with the original log price, warmup width, selected order, and training endpoint are persisted in artifacts/comparison CSVs and walk-forward logs. The notebook displays artifact diagnostics. Disabled by default; labels and existing indicators are unchanged.
  * **Remaining:** Run matched feature ablations, compare validation/out-of-sample learning and P&L, inspect per-ticker diagnostics, and assess sensitivity to threshold/order. ADF rejection is a heuristic, not proof of stationarity or profitability; candidate testing is not multiple-testing-adjusted. Correlation is a memory proxy, not a guarantee of useful information. No automatic fallback to ordinary differencing: insufficient history, constant series, or no passing candidate fails clearly in auto mode.

* **Sample Weighting:** Weight each sample's loss by the absolute magnitude of its theoretical return (`|r_i|`) so that the model focuses more heavily on high-impact trading opportunities.

  * **Current status — IMPLEMENTED, PYTORCH RUNTIME CHECK PENDING:** Optional `--sample-weighting net_return|volatility|uniqueness` uses absolute net event returns, absolute existing label scores, or net magnitude times inverse overlap. Requires Triple Barrier diagnostics. Weights are aligned after sequence building and known-label filtering; positive-event clipping thresholds, magnitude scale, and final normalization are fitted on train only. Non-events retain a neutral base weight; zero magnitudes retain a floor, with explicit uniform fallback if all training magnitudes vanish. Both Manual ANN and the shared PyTorch trainer multiply sample weights by existing class weights in loss/gradients; validation early stopping uses the frozen train normalization. Test metrics and inference remain unweighted. Static comparison, walk-forward, grid-search, artifacts, CSV diagnostics, and notebook display are connected. ANN/integration tests run successfully; dedicated PyTorch runtime tests remain blocked by the local dependency import. See [sample weighting](sample-weighting.md) for exact formulas and semantics.
  * **Remaining:** Execute PyTorch tests once the local environment is available; benchmark `none`, `net_return`, `volatility`, and `uniqueness` on identical splits/seeds/models. Tune limits on validation only and check class balance, learning gaps, stability and out-of-sample P&L. No measured improvement is claimed yet.

* **Feature Expansion:** Enrich the input space with additional company-level and market-level features, such as **valuation ratios** (P/E, P/B, EV/EBITDA), profitability and growth metrics, **news and earnings-call sentiment**, sector performance, market breadth, and broader macroeconomic indicators. Consider adding **sector momentum or sector-wide surge signals** to capture cross-sectional and regime effects.

  * **Current status — IMPLEMENTED, HISTORICAL SOURCE COVERAGE/BENCHMARK PENDING:** `--feature-set expanded` activates 122 candidate inputs across technical, market, sector, fundamentals and sentiment families in comparison, walk-forward and grid-search CLIs. `--feature-groups` supports family ablations. Offline enrichment accepts publication-dated fundamental snapshots and news/earnings events; VADER 3.3.2 supplies a free local English sentiment baseline, with externally computed scores also accepted. The existing undated Yahoo fundamentals are ignored in expanded mode. Train-only coverage/constant-column filtering, median imputation, frozen holdout columns, metadata and notebook coverage reports are implemented. The technical default remains unchanged. See [feature expansion](feature-expansion.md) for schemas, formulas and caveats.
  * **Optional-source workflow — IMPLEMENTED:** No download required. Comparison/walk-forward/grid-search accept local `--fundamentals` and/or `--sentiment`; no paths use embedded sources or continue without those families. `--no-external-features` disables embedded historical fundamentals/sentiment for a controlled baseline. Explicit missing/malformed paths fail; availability reports, file hashes, schema templates and notebook diagnostics are provided. Synthetic tests cover operation with neither, either or both sources and strict publication-time joins.
  * **Remaining:** Historical downloads are deliberately deferred. Supply genuine historical fundamental/news/earnings datasets; validate macro vintages, sector membership, currency/share consistency and feed completeness. Run matched feature-family ablations on validation/walk-forward and across seeds, then evaluate a frozen configuration on final test. VADER is not finance-specialized; sentiment quality needs validation. No profitability/learning improvement has yet been measured.


# Architecture & Objective Functions

* **Sharpe / P&L Loss:** Replace standard **Cross-Entropy Loss** with a custom objective function that directly optimizes the **Sharpe ratio** or **net P&L**, including transaction costs.

  * **Current status — IMPLEMENTED, BENCHMARK PENDING:** `scripts/run_loss_comparison.py` compares unchanged `cross_entropy` training with `pnl` and `sharpe` objectives for Manual ANN, RNN, LSTM, GRU and Transformer. Financial objectives optimize continuous positions, net of proportional turnover costs including terminal liquidation. A full chronological portfolio supplies the return mean/Sharpe gradient; bounded activation blocks replay dropout and accumulate one global update per epoch. Train-only preprocessing, validation early stopping and frozen final evaluation are retained. Expanding walk-forward now retrains financial models per historical chunk and evaluates one continuous out-of-sample position path. Walk-forward grid search ranks financial validation objectives, removes irrelevant label/decision axes, and evaluates only its frozen winner on final test. The CE default and legacy discrete backtest remain unchanged. See [financial losses](financial-loss.md) for formulas, execution, CLI, safeguards and artifact semantics.
  * **Remaining:** Run matched multi-seed static and walk-forward benchmarks against weighted cross-entropy; tune financial learning rates and regularization on validation. Financial multi-ticker walk-forward is intentionally rejected until ticker-isolated synchronized sequence construction exists. No profitability improvement is established. Static `--final-test` remains opt-in and sealed by default; walk-forward grid search retains its existing validation-winner/final-test protocol.

* **Overfitting Control:** Large and highly flexible models are particularly prone to fitting financial noise rather than persistent patterns. Explicitly prioritize **out-of-sample robustness** through model simplification, stronger regularization, feature selection, early stopping, and rigorous time-aware validation.

  * **Current status — IMPLEMENTED, OPT-IN:** `--overfitting-control` now applies compact model defaults without overriding explicit parameters, train-only variance/relevance/correlation feature selection, and best-checkpoint train-vs-validation loss diagnostics. Static validation freezes and reuses the selected columns on final test. Walk-forward refits selection inside each historical train fold. Multi-seed model comparison runs every validation first, requires configured seed coverage, validation macro-F1 dispersion, and train-vs-validation macro-F1 gap, then evaluates final test only for stable candidates. States and decisions are saved in CSV/JSON/artifacts. See `docs/overfitting-control.md`.
  * **Remaining:** Benchmark thresholds and compact defaults across tickers/regimes; add explicit regime-conditioned stability criteria and feature-group ablation reports. No profitability improvement is claimed yet.

* **Strict Regularization:** Increase **Dropout** (`0.3–0.5`), apply stronger **L2 regularization**, and use aggressive **Early Stopping** based on validation loss.

  * **Current status — IMPLEMENTED, OPT-IN:** Validation-loss early stopping and best-checkpoint restoration remain active for every neural model. Compact profile uses Manual ANN/Transformer dropout `0.30`, weight decay `1e-4`, patience `15`, and smaller capacity; recurrent models use smaller hidden state, AdamW weight decay, and patience `15`. Manual ANN now supports decoupled `weight_decay` on weight matrices only. Defaults remain unchanged outside opt-in mode.
  * **Remaining:** Benchmark dropout `0.3–0.5`, decay, patience, and capacity grids across validation/walk-forward folds; recurrent one-layer dropout remains intentionally ineffective, so recurrent regularization uses capacity and weight decay unless multiple layers are explicitly selected.

# Validation & Evaluation

* **Purged & Embargoed Cross-Validation:** Remove training samples whose time windows overlap with validation samples, and apply an embargo period around validation folds to eliminate temporal data leakage.

  * **Current status — IMPLEMENTED AS OPT-IN EXPANDING CV:** Both model and loss comparators accept `--cv-folds` for nested chronological folds: historical training, separate internal early-stopping validation, then an untouched outer scoring period. Triple Barrier training purge uses actual first-touch end dates, with conservative unknown-end exclusion and carry-state interval tracking. A reusable closed-interval purger supports post-validation embargo; `--cv-gap-bars` separately excludes targets before validation boundaries. Post-validation embargo has no additional effect when all training is strictly in the past. Global date boundaries isolate multi-asset folds, preprocessing is refitted within historical folds, candidates must complete every fold/seed, and final-test evaluation is opt-in after persisted selection. Existing non-CV behavior remains available. See [purged CV](purged-cv.md).
  * **Remaining:** Benchmark stability and runtime against the original single-validation protocol; choose gap/embargo settings without inspecting final test. CPCV/future-trained folds are not enabled. The streaming-chunk walk-forward API retains its existing purge behavior; the new comparator mode supplies nested expanding-fold hyperparameter selection. No performance gain is claimed from implementation alone.
